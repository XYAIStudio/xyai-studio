# @xyai/dsh-composer

[English](README.md) | 中文

## 概述

本包在 DSH 原生对话框旁增加紧凑的 XYAI 控件，不替换 DSH 输入逻辑。能力菜单可搜索本地操作和短语，通过写入 `/` 打开现有技能与命令链路，通过写入 `/plan` 打开规划模式，可插入 Host 持久化的快捷短语；文件、知识库会打开已挂载的真实页面；会话插件选择缺少提供方时会解释不可用原因。运行环境支持浏览器语音识别时，语音先进入带计时、无声和拒绝结果的校对区，只有用户点击“插入草稿”后才修改 DSH 草稿。状态栏显示 DSH 为当前 Harness，把其他适配器标为不可用，并从实时输入状态读取字数、附件数、排队消息数与忙碌状态。仅在输入忙碌或队列非空时显示浮层提示。

模型与思考强度、计划模式执行、权限预设、附件、上下文计量、发送、停止和排队消息继续由 DSH 负责。本包只通过公开插槽与输入操作组合在这些控件旁边。

## 设置

Host 注册经过校验的 `xyai-composer` 设置命名空间。用户最多保存 50 条快捷短语；名称长度为 1–40 个字符，内容长度为 1–2000 个字符。设置页可新增、编辑或删除短语，在写入 Host 前拒绝重名或第 51 条；Host 持久化失败时保留当前编辑内容并显示失败信息，不会显示虚假的成功结果。

## 可用性

知识库操作会触发已挂载知识库插件公开的 `xyai:open-knowledge` 事件。会话级插件选择会保持禁用，直到真实 DSH 提供方注册对应能力。本包当前只允许使用 DSH Harness。新增 Harness 必须由适配器负责执行、状态恢复、权限映射与失败报告。语音识别是否可用取决于安装包内的 Chromium 运行环境；不支持时会显示不可用说明，文字输入仍可继续使用。

## 模型体验

本包不增加模型可见上下文或工具。插入内容只有通过 DSH 原生草稿与提交链路后才会对模型可见。

#### KV Cache 影响

除用户最终通过 DSH 提交的文字外，没有额外影响。

## 运行时归属

- `conversation.input.left`：能力菜单、规划斜杠与快捷短语。
- `conversation.input.right`：校对式语音输入。
- `conversation.composer.dock`：Harness 目录与实时输入统计。
- `conversation.input.overlay`：忙碌或排队提示。
- `settings.section`：持久化快捷短语管理。

## 已知限制与延期工作

- 知识库通过 `xyai:open-knowledge` 打开已挂载提供方。会话插件选择、其他 Harness 适配器和文件选择器在真实提供方注册前保持禁用；菜单说明缺少提供方，不模拟成功。
- 语音插入会把校对后的文字追加到 DSH 草稿；公开输入面没有光标位置写入。
- 浏览器语音识别取决于安装包内的 Chromium 运行环境。
- 本包不发布 `./invariant`；插槽生命周期与设置校验仍由提供它们的 DSH 服务负责。
