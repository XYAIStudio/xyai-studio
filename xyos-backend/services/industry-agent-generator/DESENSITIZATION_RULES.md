# 数据脱敏规则

> 依据 FineDataLink《数据脱敏规则是什么？一文解析数据隐私保护核心要点》提炼，作为行业智能体生成的脱敏规则依据。
> 参考：https://www.finedatalink.com/blog/article/69eeccd51916e24b2216d410

## 一、敏感数据范围（哪些必须脱敏）

| 类别 | 示例 |
|---|---|
| 个人身份信息 | 姓名、身份证号、手机号、住址、邮箱 |
| 账户信息 | 银行卡号、支付账号、密码 |
| 企业主体信息 | 公司/单位/机构名称、统一社会信用代码、组织机构代码 |
| 商业机密 | 合同、财务报表、客户名单、订单、研发数据、经营数据（营收/利润/成本/产能/销量/报价） |
| 专有标识 | 产品名、商标品牌、项目名 |
| 地理定位 | 地名（省/市/区/县/镇等行政区划） |

## 二、核心脱敏原则（三大底层规则）

1. **精度原则（业务可用性）**：脱敏后数据格式不变、类型不变，不影响下游分析、测试、统计；
2. **合规原则**：数据最小化、不可逆性、可溯源；
3. **技术原则**：按数据类型与场景选择合适脱敏方法。

## 三、脱敏方法（按数据类型）

| 方法 | 适用 | 示例 |
|---|---|---|
| 字符屏蔽 | 手机号/身份证/银行卡 | 138***1234、4211**123X、6222 ** ** 1234 |
| 代号替换 | 企业/地名/人名/项目/产品/品牌 | 【公司N】【地点N】【人名N】（映射存私密区，可逆） |
| 哈希处理 | 密码、不可逆标识 | SHA-256 |
| 数值扰动/区间化 | 金额、经营数据 | 原值 ±扰动，或替换为区间/【数据N】 |
| 假数据生成 | 测试场景 | 张三→李四（随机合规数据） |
| 分段脱敏 | 保留首尾、中间打码 | 头尾可见、中间掩码 |

## 四、合规要求（四条不可违背）

1. **数据最小化**：只处理业务必需的数据，超出部分必须脱敏或屏蔽；
2. **不可逆性**：脱敏后不能通过技术手段还原（原名对照表存私密区，不随分发包分发）；
3. **可溯源**：每次脱敏留日志，可证明"谁、何时、怎么做的"；
4. **业务可用性**：合规前提下数据仍可用于运营、分析、创新。

## 五、落地实践（自动 + 人工双重校验）

1. **分级分类**：高度敏感 / 一般敏感 / 普通数据，分级管理；
2. **分场景**：开发测试、外包、数据分析、共享、展示，按场景选择脱敏强度；
3. **自动脱敏 + 人工校对**：自动识别后人工复核，重点排查「漏脱敏」与「过度脱敏」两类问题；
4. **日志留痕**：全流程可追溯，满足合规审计。
