# XYAI Studio 官网内容对齐建议（v0.3）

核对页面：<https://www.cnxyai.cn/>  
核对日期：2026-09-02  
目的：让官网只承诺已交付或可明确配置的能力；将“演示”“内测”“规划”与可用桌面端能力分开。

## 结论

首页的品牌方向和桌面端定位是对的，但产品状态停留在旧路线图，且部分尚未完成端到端验证的能力被写成已稳定交付。翻翻和智能体定制的“预留/内测”定位按当前产品策略保留，不纳入本轮对齐。建议本轮不改视觉骨架，优先替换文案、状态标签、下载说明和路线图。

## 能力区逐项修改

### 1. 三引擎统一对话

当前文案中的“只列出已安装且健康的运行时；切换后下一轮真实生效”属于较强承诺。

建议标题：`统一工作区与可用运行时`  
建议正文：`在同一桌面工作区内组织对话、会话和任务。系统仅展示当前可用的运行时；实际可用范围取决于本机已安装组件与用户配置。`

若完成三引擎切换的端到端验收后，再恢复“下一轮真实生效”的表述。

### 2. 模型市场

当前“国内云、国外云与自定义 Provider 分类展示”可保留为产品方向，但不应暗示平台会代替用户配置云端模型。

建议标题：`模型广场与本机硬件建议`  
建议正文：`系统读取本机 CPU、内存和已识别显卡信息，推荐更匹配的本地模型。模型下载、部署和注册均由用户确认后执行；云端模型按用户自己的 Provider、账号与密钥配置。`

建议在下载区增加注记：`本地 GPU 推荐当前以已识别硬件为准；实际速度和可用显存会受驱动、量化版本及其他程序占用影响。`

### 3. 统一审批中心

“命令、文件、网络、MCP 四类审批卡三端一致”过于具体，且“三端一致”很容易被验收追问。

建议标题：`高风险操作确认与运行日志`  
建议正文：`对需要确认的高风险操作提供人工确认入口，并在设置中保留故障日志与处理建议。不同运行时和连接器的实际权限能力以页面状态为准。`

### 4. 跨引擎上下文交接、用量与成本分析

这两张卡不建议放在“已交付能力”首屏。可改为“正在完善”卡，或移入路线图。

建议文案：`跨运行时交接与用量分析正在完善中。正式可用前，将在应用内以状态与版本说明为准。`

### 5. XYOS 业务联动

“直连业务空间，生成物自动归档可追溯”属于较强的生产承诺。

建议标题：`业务空间连接`  
建议正文：`可在桌面端组织知识库、智能体和交付物；连接 XYOS 或其他业务服务时，需要由用户完成相应账号与服务配置。`

## 建议替换的路线图

```text
v0.3（当前预览版）
统一桌面工作台、工作台对话入口、本机知识库挂接与检索、模型广场与本机硬件建议、故障日志分析。

下一阶段
继续完善多运行时的可用性检测与受控切换；增强云端知识库/业务空间连接；补齐模型下载部署、运行状态和交付物的用户可见反馈。

后续规划
在完成端到端验收后，逐步提供跨运行时交接、用量与成本分析、团队分发、工作流编排和正式发布签名。
```

不要继续在官网写死 0.4、0.5、0.6 等小版本的能力归属，除非已有稳定的版本计划与验收负责人。对外建议只展示“当前预览版 / 下一阶段 / 后续规划”。

## 下载区建议成稿

```text
XYAI Studio for Windows
v0.3.0 预览版 · Windows 10/11 x64

下载前请核对版本、发布日期和 SHA-256。当前安装包未进行 Windows 数字签名，首次安装可能出现系统发布者提示。

推荐配置：16GB 内存；本地 GPU 模型的推荐结果以应用内硬件检测为准。模型不会自动安装，用户确认后才会下载、部署和注册。
```

## 信息架构与状态标签

建议全站使用三种统一标签，避免“预留”“完成”“演示”混杂：

- `v0.3 可用`：已进入当前桌面端，且有可见入口。
- `预览 / 需配置`：功能入口存在，但依赖本机组件、账号或外部服务。
- `规划中`：尚未作为用户可依赖的交付能力。

每个能力卡片都增加一个状态标签；下载区和路线图使用同一套标签。这样用户能自然区分“现在能做”“需要自己配置”“未来会做”。

## 修改优先级

1. 当天修改：Hero、工作区演示提示、下载说明和路线图。
2. 本周修改：六张能力卡按上述边界重写，增加统一状态标签。
3. 后续补齐：单独建立发布页，列出每个安装包的版本、日期、SHA-256、已知限制和安装说明；官网不再承担版本验收说明书的角色。
